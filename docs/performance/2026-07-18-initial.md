# initial — 2026-07-18

First real run of all four `scripts/bench/` scripts (see
[scripts/bench/README.md](../../scripts/bench/README.md) for method and
limitations of each). These are development-machine numbers, not lab
conditions — no isolation from background processes, single machine,
small sample sizes. Treat as a baseline for spotting regressions, not as
a performance claim.

## Machine

- OS: Windows 11 Pro, build 10.0.26200 (Windows 11 Pro 26200)
- CPU: 12th Gen Intel(R) Core(TM) i5-12600K
- RAM: 31.7 GB
- Build: commit `4e4e3cfc0179c442463c7160020b95a2a1e4b70e`
  ("Wire phase 2: commands, sync events, message view, composer, outbox
  UI"), release binary rebuilt from this commit
  (`cargo build --release -p axomail-desktop`) and frontend rebuilt from
  the same commit (`pnpm build`) immediately before these runs, so all
  four measurements reflect the same tree.
- Context: dev machine, normal background load (editor, browser, etc.
  running), not a dedicated benchmarking rig.

Notes: **the `sqlite3` CLI was not installed on this machine**, so this
ran the `node:sqlite` fallback path, not the CLI `.timer` path — see the

`mail-storage` query layer. `deepPage` (`OFFSET 49950`) being roughly
25-30x `firstPage` (`OFFSET 0`) is the expected `OFFSET`-pagination cost
signature and matches the concern ADR-0008 flags for revisiting at scale
— not itself a regression.
